# 见微 v0.3.1：修正 WeRSS 镜像架构

WeRSS 当前固定上游包含 x86_64 程序，v0.3.0 的 arm64 标签不代表原生 ARM 支持。本版只发布 WeRSS 的 `linux/amd64` 镜像，本机和生产 Compose 同步指定该架构。Web、Worker 和迁移工具继续提供 amd64/arm64 镜像。

## ARM 部署边界

Apple Silicon 或其他 ARM 主机启用 `wechat` profile 时，需要 Docker 环境支持 amd64 仿真。仿真可能增加 CPU、内存消耗，本次修正不代表 WeRSS 性能提升或原生 ARM 支持。

没有仿真能力的 ARM 服务器可以使用核心服务，并连接外部 amd64 WeRSS：不启用本地 `wechat` profile，设置容器可访问的 `WERSS_DOCKER_BASE_URL` 和对应 Access Key。生产网络与授权说明见 [生产部署](https://github.com/workagi/jianwei/blob/v0.3.1/docs/production-deploy.md)。

## 安全依赖修正

Next lint 插件的目录查询改用项目已有的 `tinyglobby`，从依赖图移除 `fast-glob → micromatch → braces`。这样消除本项目对 [CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) 漏洞代码的依赖，完整安全审计保持原样。兼容补丁固定于 `@next/eslint-plugin-next@16.3.6`，安装时由 pnpm 应用，升级该插件时需核对目录匹配测试并评估移除补丁。

## 从 v0.3.0 更新

本次没有业务逻辑或数据库迁移变更。沿用原项目名、环境配置、加密密钥和数据卷；不要删除 WeRSS 数据卷，否则会丢失授权与订阅。

```bash
git fetch origin --tags
git switch --detach v0.3.1
```

本机源码部署运行 `./start.sh`。已使用版本镜像且确认可拉取时，将 `.env` 中的 `JIANWEI_IMAGE_TAG` 改为 `v0.3.1` 后再次运行 `./start.sh`。

生产源码部署使用原有参数执行 `docker compose --env-file .env.production -p jianwei -f docker-compose.prod.yml up -d --build --wait`；版本镜像部署将 `JIANWEI_IMAGE_TAG` 设为 `v0.3.1`，执行：

```bash
docker compose --env-file .env.production -p jianwei \
  -f docker-compose.prod.yml -f docker-compose.images.yml \
  up -d --no-build --pull always --wait
```

保留原来的 `COMPOSE_PROFILES`，启用公众号采集后核对 WeRSS 后台、原有订阅和 Worker 状态。Release 与镜像发布不会自动升级已有实例。GHCR 包为私有时仍需授权拉取；匿名访问需以实际包可见性为准，详见 [版本发布](https://github.com/workagi/jianwei/blob/v0.3.1/docs/release-process.md)。
