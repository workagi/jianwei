# 见微 v0.2.0

这版借鉴 AIHOT 的事件持久化与付费调用回执思路，保留见微一次内容理解和个人监控的数据结构。事件聚合不增加模型调用。

## 新增与修复

- 任务相关性分数完整传到阅读层；模型编辑理由独立保存，不再被监控命中理由覆盖或遗漏。
- 后台保存稳定事件归属；精选页按已保存事件读取，候选扫描限制为每个平台300条，不再打开页面时进行相似度聚类。
- 版本号与明确日期冲突检查，避免同一模板下不同模型版本发布被误合并；提供人工拆分命令，刷新不覆盖人工归属。
- 所有模型 HTTP 请求统一通过响应回执和每日请求预算，包括新内容分析、自动/手动补跑、标题翻译及兼容请求重试。
- 已收到的响应可以跨重启复用；网络超时或结果不明时停止自动重发，提供显式核对与恢复命令。
- 后台显示实际请求、tokens、已知部分费用与未确认费用。缺少单价或用量时不将费用标成免费。
- 一并纳入采集分页、来源身份一致性、登录限流、客户端IP、备份恢复及卸载范围等可靠性修复。
- 更新 Next.js 与间接依赖到本次依赖审计要求的安全修复版本。
- 新增版本标签触发的 Release 工作流，要求标签版本一致、更新说明存在且对应提交CI成功。

## 升级

1. 备份 PostgreSQL 和 `APP_ENCRYPTION_KEY`，保留升级前代码版本。
2. 停止旧版 Web/Worker，切换到 `v0.2.0`。
3. 使用源码构建升级：

   ```bash
   docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build --wait
   ```

4. 启动迁移会执行新增迁移 `0028_editorial_receipts_events`，创建事件与模型回执表，并从历史模型理由回填文档编辑理由。
5. 检查 `/api/health`、后台登录、Worker心跳、实际监控结果与模型用量。Worker自动为最近14天内最多2000条候选建立事件归属；旧文章或超出窗口的内容仍可按单篇阅读。

## 配置与运维

- `MODEL_DAILY_REQUEST_LIMIT=1000`：全部模型入口共享每日请求上限，按北京时间零点重置。`0`停止新请求；复用已有响应不占新增额度。此上限限制请求次数，不是美元金额保底。
- 设置 `SUMMARY_INPUT_COST_PER_1M_USD`、`SUMMARY_OUTPUT_COST_PER_1M_USD` 后，按服务商返回tokens估算费用；未知用量或单价单独标记。
- 事件刷新：`pnpm events refresh`。人工拆分：`pnpm events split <item-id>`。
- 查看回执：`pnpm model:receipts list`。核对服务商记录后，显式放行超过30分钟的未确认请求：`pnpm model:receipts retry <receipt-key>`。然后执行对应补跑；再次请求可能产生新的费用。
- Docker 部署可在 Worker 容器内执行上述命令，例如 `docker compose --env-file .env.production -f docker-compose.prod.yml exec worker pnpm model:receipts list`；容器使用部署时的数据库与配置。
- 原始模型响应保存在本地数据库，随数据库备份一起保护；没有保存API密钥和完整请求正文。

## 回滚与边界

新增迁移保留旧字段和数据。功能回滚时停止新版进程，切回升级前代码并重新构建；保留新增表。需要恢复整个数据库状态时，使用升级前备份与同一加密密钥，在停机状态恢复。不要直接删表或倒跑迁移。

这版尚未加入语义事件关系判断、双评分和日报；标题规则仍可能误判。采集和内容分析仍在同一监控任务链路内，独立分析队列是后续演进内容。
