# 变化阅读优化与升级说明

2026-10-02，本地实现，基于 v0.2.0（4c567273）。本次将第二轮 AIHOT 对比中发现的选择顺序、事件身份和原文修订问题落实到数据与阅读流程，尚未发布或迁移现有线上数据库。审查时的复现记录保留在 [第二轮产品审查](aihot-product-review-2026-10-02.md)，其中旧结果是改动前基线。

## 使用方式

首页默认进入“关注变化”，显示最近14天内未读的事件变化。首次使用时已有事件没有阅读基线，会作为首次收录显示；卡片下方的“全部标记已读”会跳过当前事件所有剩余版本，界面会提示最近三版之外的未读数量。打开页面本身不会消耗未读状态。

选择一个或组合多个现有监控，可以汇总 X、微信、搜索与榜单/RSS 的命中内容。组合使用并集，进一步选择平台时要求命中来自该平台；相关分取当前范围内最高命中分，推荐理由对应同一命中。组合范围保存在 URL，可收藏链接；各监控的必含词/排除词是硬条件，排序偏好是软条件。这里没有自然语言目标推理或独立任务表。登录管理后台后可以关注事件、标记已读，并勾选“只看已关注事件”。当前为单工作台共享状态，没有多用户独立阅读账户。文章右上角收藏仍绑定当前原文，事件关注绑定稳定事件 ID。“已关注事件”目录包括已读事件，便于回看与取消关注。写操作被拒绝时可点击“登录并返回”，保留当前页面和筛选。

精选、最新、归档与收藏统一在最终可见卡片上加载最近三个进展版本的材料标题、证据摘录和原文链接。点击“查看完整变化记录”进入事件详情，按三个版本一页查看更早证据。启用模型后，原有一次内容分析会同时提取事件身份与最多三项价格、开放范围、能力、许可、指标或时间信息；这些字段必须附带可在输入中找到的原文引用。在唯一分析入口，复用阶段规则拒绝引用中的限制/预告被标成已开放，并丢弃引用中没有相同数字的具体值；这只拦截局部矛盾，不等于完整语义或事实核验。模型没有提供可用字段时继续使用标题阶段规则。界面给出“材料提到……”或新增信息提示，读者仍需核对原文。无新变化时仍可使用精选、最新和全部信息阅读。

## 行为变化与实现

| 原问题 | 当前行为 | 关键实现 |
| --- | --- | --- |
| 先截成36条再找 TOP，优质候选被截掉 | 先从完整的有界合格候选选 TOP，再保留 TOP 并填充时间流；来源配额是软约束 | `content-clustering.ts`、`reader-data.ts` |
| 个人任务高相关、文档公共分较低的内容被公共门槛或候选截取排除 | 公共精选使用文档质量，任务精选使用任务相关性；候选排序、准入和展示复用同一评分表达式，分析质量要求仍保留 | `db/queries.ts` |
| 转述来源数量影响推荐顺序 | 取消关联来源数加分，保留来源链接供核对 | `content-clustering.ts` |
| 代表稿替换导致事件锚点、时间及阅读状态改变 | ID、活动时间、进展版本与代表稿分离；重复报道不递增进展版本 | `event-projection.ts`、`event-reader.ts` |
| 跨语言、同源报道仅凭标题漏合并，相似模板可能误合并 | 可用事件字段按主体、动作、对象、版本及明确发生日期归并；字段缺失时保留标题规则 | `event-signals.ts`、`content-clustering.ts` |
| 预告与开放、发布与否认被当作同一次发生 | 阶段冲突不走同阶段合并；共同事件身份直接关联根节点形成进展，字段缺失时使用明确版本规则 | `event-claims.ts`、`event-changes.ts` |
| 同阶段的新细节被视为重复报道 | 按信息类别与规范值去重；新增或不同的具体值保存原文证据，同一篇材料只推进一次事件版本。迟到的同文分析建立基线，不产生未读提醒 | `event-changes.ts`、`event-projection.ts` |
| 开放状态恢复因曾经出现过而不提醒 | 带明确发生日期的开放状态与最近状态比较；暂停后恢复推进版本，同状态确认与迟到旧状态保存基线。单次刷新复用同一事件历史 | `event-changes.ts`、`event-projection.ts` |
| 人工拆分沿用旧成员进度，新事件没有初始变化 | 拆分重置处理版本与字段指纹，命令随后执行现有有界刷新；新事件建立自己的进展与阅读基线 | `scripts/events.ts` |
| 较短的原文更正被旧长文压住，新正文配旧摘要 | 同一内容拥有来源的完整更正可替换较短内容；保存修订，清空旧分析，再进入小批量补跑 | `content-revisions.ts`、`repositories.ts` |
| 旧采集、旧全文补抓或慢模型结果覆盖新版本 | 观察时间及输入哈希/修订版本写入守卫，旧结果不提交 | `wechat-content-write.ts`、`summary-backfill.ts` |

修订哈希比较规范化标题和可见全文，忽略 HTML 排版与空白变化，保留有意义的否定和大小写。修订表保存原始 HTML，变化卡只显示证据摘录。标题或正文的变动可能是措辞调整，系统标为“原文修订”，不自动断言事实更正。

## 升级

1. 备份 PostgreSQL 与 `APP_ENCRYPTION_KEY`，保留升级前代码；停止旧版 Web/Worker。
2. 本次新增迁移为 `0029_event_reading_revisions`、`0030_content_observation_fence`、`0031_content_ownership`、`0032_fulltext_revision_evidence`、`0033_evidence_event_signals`。最后一项只为文章保存提取字段、事件成员保存已处理字段的指纹，复用已有进展表。源码部署按现有流程运行 `pnpm db:migrate`；Docker 部署使用迁移服务，完成后再启动新版 Web/Worker。
3. Worker 会自动刷新事件；需要立即处理已有候选时执行 `pnpm events refresh`。该命令每次处理最多200条尚未归属、正文修订未处理或字段指纹变更的已保留材料；按观察时间推进，重复运行可处理积压。关系判定上下文仍有上限（近期2000条、已关注2000条），不重新划分人工事件归属，也不会追溯出数据库中从未保存过的历史正文版本。
4. 检查后台登录、健康状态、Worker心跳和一个实际关注任务。验证标记已读后重复报道不出现，新增进展或原文修订会出现，并核对原文链接。

功能回滚时停止新版进程，切回升级前代码并构建；保留新增表和字段。恢复整个数据库需要在停机状态使用备份与同一加密密钥，不直接删表或倒跑迁移。

本轮处理闭环与阅读修正没有新增迁移、表或模型调用层。原文修订自动分析仍会产生原有一次分析的用量，复用当前领取、预算与重试次数。规则版本为 `v7-progress-worklist`；沿用已保存的事件身份与旧进展记录，不自动重建历史归属。

## 已验证

- 第一轮实施使用独立 PostgreSQL 17 数据库执行所有迁移和种子；全量55个测试文件、367项测试通过，包括数据库集成与慢模型结果竞争测试。
- 覆盖第37条高分候选、同源第6条高分候选、公共/任务门槛差异、稳定锚点、重复报道不重新未读、短原文更正、全文补抓及旧分析写入守卫、状态接口鉴权和未来版本拒绝。
- TypeScript、ESLint、生产 Web 构建、Worker构建、迁移一致性检查与开源审计通过。
- 用隔离样例在真实浏览器操作：展开证据、未登录写入被拒绝、登录后标记已读并从变化列表消失、任务 TOP 的事件锚点、关注切换和关注筛选。未访问真实模型或采集上游；未修改生产数据。
- 成对事件规则的16个构造难例仍有1个误合并、2个漏合并，见 [事件评测](event-evaluation.md)。这不是线上准确率。

继续优化增加了事件字段提取与同阶段细节记录；全量56个测试文件、375项测试通过，含 PostgreSQL 集成。验证模型分析仍只发一个请求；跨语言/同源明确身份、不同发生日期和版本、迟到分析不重新未读、新开放范围或月费变化出现、重复英文转述与旧价格转述不再次提醒。另有3对实际发布材料的人工字段标注回归，区别于真实模型提取评测，见 [事件评测](event-evaluation.md)。

本轮修正后，全量56个测试文件、380项测试通过，使用新建 PostgreSQL 17 数据库执行全部迁移和种子。新增回归覆盖带日期的开放→暂停→恢复、同状态确认与迟到旧状态、真实人工拆分命令及新事件首次未读、任务高相关而公共分低的候选在截取前排到首位。TypeScript、ESLint、Web/Worker构建、迁移一致性及开源审计通过；测试未调用真实模型或采集上游。

遵照“不要叠加过多保护代码”的要求，本次只在模型输出入口校验字段和原文引用，下游复用现有事务、版本校验与模型预算；没有新增重试层、调用队列或守护流程。HTML内容取舍及抓取状态也改为统一使用已有合并判断，移除重复 SQL 分支。

## 仍需完善的边界

- 目前一次分析可提取一个主要事件及最多三项具体信息，没有完整事实图谱或状态机。带明确发生日期的开放状态支持暂停后的恢复，但无日期或同一天内的状态往返仍受去重限制。具体信息仍按事件内已出现过的值去重；价格恢复旧值需要区分套餐、条件与时间，当前不据此自动提醒。规范名称或值的提取不一致仍会漏合并或重复提醒；合集、多个事件、超出输入截取范围的细节仍可能遗漏。字段缺失时，标题规则的跨语言和相似模板问题继续存在。实际模型质量需要更多真实样本及独立留出集验证。
- 历史误合并不会被刷新自动拆开；使用 `pnpm events split <item-id>` 人工处理，命令会随后刷新；未保留材料不在刷新范围内；已归属旧稿的修订不再受发文窗口限制。已有人工决定继续保留。
- 精选、变化与已关注视图候选最多5000条材料，投影每轮200条待办，关系上下文仍有上述上限；“先选重点”在该有界范围内成立，不能宣称全库召回。范围外旧材料仍可按单篇阅读。
- 原来源更正需要连接器实际返回新内容，并提供可判断的完整状态；截断材料、无法抓取的正文及来源身份不明时，保守保留旧完整文本。
- 事件关联不新增模型请求。字段随原有摘要分析返回，普通模型默认输出上限从420（Claude300）提升为1000 tokens，实际输入与输出 tokens、费用仍走原有用量计量。不会为旧版成功分析自动重跑；原文修订或原有补跑才会重新分析。原文修订会让旧分析失效，并非所有处理都免费。
- 保留现有状态、版本与 claim 机制，尚未加入独立队列服务、主动通知、日报或自动行动；后续原稿先落库的调整见文末。

## 本轮处理闭环补齐

- Worker 接管已保留内容的 pending 原文修订与可重试失败；不会为所有历史 pending 首版内容自动补模型。收到完整更正后，无需再采集或人工点补跑。默认按原有15分钟、5条批量运行，费用和吞吐受现有预算/次数限制。
- 每个监控提交完成后触发有界事件处理，减少快来源等待整轮慢监控的时间；分析补跑后的整轮刷新仍保留。原始采集仍先等待首次分析再入库，本轮没有把这条链路重构为独立队列。
- 已关注、具有明确主体/对象/版本的事件，可继续关联超过14天后的带日期开放状态或更正；不是全产品长期监控。未提供明确字段的新事件仍使用近期规则。
- 首次收录旧材料按原发文时间归档；已归属原文修订按本次观察时间更新。原文发布时间与事件时间不同会分别显示。首页“本页最新记录”取展示记录时间，后台和空事件页复用内容处理统计显示理解与事件待办。多平台重复材料按来源分别统计。
- 移除排除词硬条件之后恒为零的罚分预留代码；忽略生成的 Worker dist 构建产物，防止常规 lint 将打包依赖当成源码。

下方为资源优化前的验收记录；后续结果见文末。真实模型提取和精选留出评测尚未完成，局部字段核对与功能回归不能替代它们。

本轮最终验收：57个测试文件、389项测试全部通过，使用一次性 PostgreSQL 17 执行迁移和种子。新增回归覆盖自动修订分析、2001条已处理材料不阻挡待办、201条待办分两批排空、20天前已关注事件的新开放状态与原文修订、六版历史分页、精选/收藏统一证据、组合监控并集与平台交集，以及导航保留范围。TypeScript、ESLint、Web/Worker构建、迁移一致性及开源审计通过。

另在本机生产构建上以构造的六版事件执行 HTTP 验收：详情最新/历史页、非法ID返回404、匿名写入返回401、登录后的已读状态与已关注目录、页面筛选链接与时间表达均通过。[验收结果](reviews/2026-10-02/reading-loop-http-results.json) 明确记录样例性质。本轮未重新验证浏览器交互或真实上游/模型；未访问生产库、提交远端或部署。

## 后续资源优化

变化与已关注列表先查询每批 100 个事件身份，再读取该批成员，通过本地 Gate 后累计页数；只保存当前页及下一页提示。活动时间相同按事件 ID 稳定排序，材料超过 5,000 条不再把其他事件挤出变化列表。现有精选仍使用有界候选；该调整不宣称全库精选召回，极深页或非常稀疏的本地筛选仍可能扫描多批事件。

Worker 现在先持久化新原稿，再用已有待分析状态每轮小批量处理，原先整轮 15 分钟门槛移除，失败重试仍有 15 分钟冷却。新入库、带分析版本标记的 pending 首版可自动处理，代码版本升级后仍可续跑；历史未标记 pending 首版不全库补跑，成功内容不自动重写。启用模型时 pending 首版等待分析结束再归类，停用模型后可按规则进入阅读且保留待办；已归属材料与原文修订仍按已有事件更新。没有增加独立消息队列、模型调用层或保护框架。

部署、实测和本轮最终验收见 [低资源优化记录](low-resource-optimization.md)。

稳定性补齐：慢分析在同一 Worker 内仅运行一个后台批次，采集轮询继续；停机信号传入模型调用并等待分析退出。候选中的活跃租约不会阻挡后续可领取内容。事件成员按 ID 每批 200 条读取，保留每个来源的优选材料、人工优选稿与日期基线，来源证据不因分批丢失。历史删除每表每轮最多 1,000 条。实际进程中断与压力样例见低资源优化记录的后续验收。
